# Agent Note: 标题格式可通过退格取消

Status: implemented

## Problem

Markdown 的井号前缀转成标题后不再作为可见字符存在，原编辑器在标题开头退格只会删除前一个换行，不能恢复正文。菜单切换为正文还可能残留标题附加的加粗，使用户感觉无法撤销格式。

## Decision

光标位于一到六级标题段落开头、无选区且不处于输入法组合状态时，退格先取消标题格式，不删除文字或与上段合并。再次退格恢复普通文本删除行为。菜单的正文转换恢复正文字号与字重；输入属性跟随当前段落更新，撤销和重做也恢复对应的输入样式。

标题的显示字重由块格式提供，不再在新标题转换时永久写入行内粗体。退出标题时清除标题段落的粗体和标题字号；其他行内样式继续保留。取代检查：补充现有标题即时转换的逆操作，不替代 [桌面交互](../feature/2026-09-14-desktop-interaction.md) 或其他编辑决策，无需归档。

## Alternatives considered

本次修复考虑仅让用户用菜单切换正文，但这不能解决开头退格误删换行的问题。保留原先退格合并行为也不符合标题可逆编辑的目标，因此让开头的第一次退格优先取消块格式。

## Consequences

此交互仍是富文本编辑，井号不会一直显示为源码；可通过重新输入井号和空格设为其他标题级别。退格中段文字、选区删除和输入法组合状态仍走原生编辑行为。退出标题会清除该段粗体，需要时可再用 Cmd B 添加。

## Verification

[HeadingReversalTests](../../../../Sources/HeadingReversalTests.swift) 覆盖六级标题开头退格、保留文字与段落、光标位置、正文字号、撤销与重做，以及菜单转正文和继续输入。入口为 `DeskNotes --heading-reversal-check`，已接入完整 self-test。旧代码在退格取消及菜单字重检查中失败；修复后 32 项标题恢复检查及完整 self-test 全部通过（2026-09-15，原生窗口、合成文本）。实现见 [Views](../../../../Sources/Views.swift) 和 [RichText](../../../../Sources/RichText.swift)。
