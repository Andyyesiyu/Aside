# Agent Note: 数字列表序号编辑与保存一致

Status: implemented

## Problem

删除或修改数字列表的序号后，富文本读取仍按旧列表上下文生成编号；完全删除前缀后，正文又继承列表属性。导致编辑器中的文字和已保存文档不同，刷新时恢复编号、改变后续序号或移动光标。旧版本的原生编辑回归已复现修改中间序号、删除数字、删除完整前缀这三条路径。

## Decision

保存时尊重当前可见的合法编号。编号与原顺序不同时拆分编号段，保留该项与后续项各自显示的数字。删除前缀或输入未完成时保留字面文字并取消该段落的列表结构，不重新生成被删除的标记。回车也检查可见前缀，避免遗留属性把已取消的列表恢复。

取代检查：本记录补充列表编辑边界，与 [桌面交互决策](../feature/2026-09-14-desktop-interaction.md) 和 [同步安全](../architecture/2026-09-14-notes-sync-safety.md) 的要求并行有效，不取代五级列表或同步安全策略，无需归档。

## Alternatives considered

本次修复评估了仅延迟后台刷新、强制恢复旧序号、禁止编辑序号三种方案。它们无法同时保留用户输入、解决保存差异和支持现有直接编辑体验，因此在富文本读取处消除可见文字与文档结构的不一致。

## Consequences

手动非连续编号可能成为多个编号段。苹果备忘录不能可靠回写的自定义起点仍按既有保护暂停回写，不为消除提示强行改回从 1 开始。超出整数范围或带前导零的编号保留为普通文字，避免溢出或改写用户内容。此改动不统一重排用户已经输入的编号。
